# Python candidate packages on z/OS

Generated by `tools/python_candidate_report.py`. The status column is a real
`pip install` on a z/OS system using the zopen wheel index and the published
constraints file — not an inference from PyPI metadata, which cannot tell you
whether a transitive sdist will build.

## Shared blockers

Ranked by how many candidate packages each one blocks. Porting a blocker
unblocks every package in its row, so this ordering matters more than the
number of times a package was requested.

Lacking a `py3-none-any` wheel makes something a *candidate* blocker, not a
real one: several such packages build from their sdist on z/OS because the
C accelerator is optional and they fall back to pure Python. The last column
is the only one that settles it, and it comes from actually installing them.
